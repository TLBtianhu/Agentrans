# Agent Note: 桌面欢迎窗口材质

Status: implemented

[English](2026-09-08-desktop-welcome-window-material.md) | 中文

## 问题

桌面欢迎界面的设计要求整个窗口模糊其背后的桌面。Chromium 背景滤镜只能采样渲染器内部的内容。凭证配置还需要明确的启动归属，避免跳过原生引导后又出现 Web 弹窗。

## 决策

[Electron 欢迎窗口](../../../../apps/desktop/src/welcome-window.ts)负责原生材质和控件。本地 React 渲染器显示单一 API Key 表单与纯文本 Agentrans 品牌。隔离 preload 提供本地化文案、保存、跳过，以及打开 [DeepSeek 官方密钥页面](https://platform.deepseek.com/api_keys)的无参请求。固定 URL 由主进程持有，IPC 拒绝其他窗口和子 frame。文档禁止网络请求和导航。每个沙箱 preload 都独立打包，因为 Electron 受限的 require 无法加载同目录中的拆分模块。主进程通过共享 Web 启动 URL 认证，并通过现有设置和凭证 RPC 读取已配置密钥的元数据、写入官方提供方的引用。[Web 薄壳](2026-09-10-desktop-web-wrapper.zh.md)负责 HTTP；引导不增加 Host 端点或子进程 IPC 操作。响应只包含元数据或安全结果，不包含密钥或提供方的私有诊断。

冷启动时，若所有模型 API Key 引用均未配置，则显示该表单。原生引导不读取账号状态，也不监听账号回调；现有授权保持存储。保存会在持久化成功后进入工作区，失败时保留草稿。跳过直接进入工作区，不保存草稿或完成标记；下次冷启动会重新检查密钥。保存、跳过和外链共用忙锁。Desktop preload 标记抑制自动 Web 凭证引导和欢迎须知；模型设置与显式密钥编辑仍然可用。[账号提供方](2026-09-14-deepseek-account-login.zh.md)仍可用于可选 Web 账号与 Platform 组合。原生分析在每次上报事件前读取既有收集策略，不依赖账号状态流。

生成的开发项目沿已声明的 workspace 依赖建立链接，因为单独依赖 pnpm 的提升索引会漏掉配置插件。

Desktop 在打开欢迎窗口前读取共享的 `locale.preference`。Client 在挂载前等待隔离 preload 返回偏好和系统语言顺序，之后将解析后的语言变更通知桌面壳。只有设置中的明确选择会写入偏好；自动检测保持临时状态。桌面壳自带八种语言词典，并回退到受支持的系统语言或英文。

欢迎流程与启动恢复共用 Desktop 后端控制器。Host 启动期间，主窗口在屏幕外加载恢复文档；失败时显示该文档，成功后读取凭证和语言，再选择欢迎窗口或工作区。恢复操作保留控制器的串行重试与等待子进程退出的行为。应用 preload 只向壳文档提供恢复控件，只向应用文档提供语言桥接。

## 考虑过的替代方案

**仅使用 CSS 背景滤镜。** 它无法模糊其他应用窗口或桌面，因此不能提供所需的原生效果。

**持久化凭证入口完成标记。** 跳过原生引导只对当前进程有效；保留标记会在尚未配置模型密钥时抑制下次冷启动选择。可选账号介绍流程的独立标记不会绕过该密钥检查。

**同时保留原生与 Web 凭证弹窗。** 两者独立的完成状态会在跳过原生引导后再次要求输入密钥。组合将凭证引导交给单一归属方。

**绘制替代红绿灯。** 原生控件保留平台窗口行为和无障碍能力。它们的尺寸与窗口外部圆角遵循操作系统，不严格复制 Figma 几何参数。

**独立的预览回调。** 纯视觉预览中的跳过无法证明能进入工作区，还会掩盖启动依赖缺失。预览使用与产品相同的回调和 Host。

## 后果

原生模糊强度和字体回退因系统而异。主窗口使用 sidebar vibrancy；引导保持渲染器透明，不额外叠加底色。Windows 合成效果需要平台验证。所属目录内的渲染器与文本预期覆盖单一表单及其操作；构建后 Host 的验收覆盖无账号请求时密钥元数据跨重启保持的行为。现有账号授权与独立 API Key 保持不变。引导展示不会生成 Session 事件。

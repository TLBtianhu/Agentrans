# Agent Note: 已保存观察保留源码与持久准入收据

Status: implemented

[English](2026-11-07-saved-artifact-observations.md) | 中文

## 问题

粒子检查点标识固定步数，但不能标识源码修订。把它留在组件中会在刷新时丢失实验；与改变后的源码配用会静默描述另一次实验。响应丢失后重试保存或发送，也可能产生重复事实或输入。

## 决策

明确保存的观察包含完整源码快照、运行检查点、名称和 Host 重新计算的数值。必需的 `artifact/observations` 事件替换单个 Artifact 的完整保存列表。私有 Artifact Projection 恢复源码读取和观察；wire 值不含源码读取索引与准入收据，紧凑 Session 摘要也排除观察。恢复路径不扫描日志，也不调用模型。

保存重试先比较稳定身份与捕获的值，再检查最新修订。UI 按 Artifact 持有待处理请求，与按修订创建的运行和可移动视图分离。历史预览只读并使用已保存源码；返回最新源码会恢复其独立的暂停状态。

发送使用普通输入准入。投影识别同一 Session 自有 Inbox 或用户消息中的匹配收据，因此已接受的重试不会再次入队。分支继承观察，但不会将父分支收据作为自己的准入。保存收据和消息入队之间不存在另一条成功事件。

粒子比较标识有序的两个已保存观察，包括它们的原始比较组和角色。共享纯模块要求运行版本、时间步长和步数相同，并重新计算双方。Host 通过同一 Projection 解析引用，使用已保存 control 修订准入固定组合。本 Session 自有收据对组合去重，与单条发送独立；私有索引只保存已准入键，wire 值不变。它的成本随用户明确确认的不同组合增长，不随播放帧增长。

## 考虑过的替代方案

**只持久化检查点**需要在同步恢复前另外查找历史源码。完整源码副本让已保存实验自包含；每个 Artifact 的可配置上限限制新增保存，而不丢弃旧记录。

**本地存储或第二套观察台账**会重复 Session 恢复机制，并让已保存实验脱离分支归属。Session Projection 已提供恢复、缓存检查点和 wire 更新。

**分派前持久化已发送标志**会在进程于两步之间停止时丢失输入。从已有持久 Inbox 和已消费消息推导准入，可将去重绑定到实际发生的动作。

**拼接当前预览报告**无法在任一源码变化后保留实验。已保存引用固定双方源码与采样条件。没有用户撰写结论的确定性组合不需要另一套比较账本；普通已准入消息已经保留证据。

## 影响

保存和恢复不改变模型上下文。明确发送可引用旧源码，普通 live 操作仍校验当前修订。源码副本会占用空间，满额列表会拒绝新增保存。陌生必需事件让旧读取器拒绝 Session，而不是丢失观察。比较选择属于本地状态；已保存证据和已确认消息保持持久化。相同采样条件不能证明因果关系。尚未提供删除和运行状态自动保存。

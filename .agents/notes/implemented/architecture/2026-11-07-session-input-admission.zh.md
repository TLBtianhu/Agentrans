# Agent Note: 已接受 Session 输入由唯一所有者管理

Status: implemented

[English](2026-11-07-session-input-admission.md) | 中文

## 问题

Client 可能在 Agent 接受输入后丢失响应，换消息 id 会重复操作，重新读取变化的预览还可能替换原条件。API 控制器内部的问题收据无法直接供领域复用，否则要反向依赖或再建接受索引。

## 决策

[Session 输入](../../../../packages/session/session-input/README.zh.md)统一拥有既有私有收据 Projection 与唯一执行中准入映射，当前消费者是 Session Controller 和 Artifact。领域代码拥有消息构造、当前源码校验和访问政策；共用服务只认识输入身份与发送方式，不认识 Artifact 业务规则。

普通 RPC 别名保留原有接受语义。已标识领域消息使用既有用户消息 id 与首次来源/内容摘要；已接受重试先于当前源码校验返回，即使原队列项已编辑或取消。继承事件不预约子级身份。发送方式只生效一次，持久消息没有保存它，不能伪装成可恢复的 mode 冲突检查。

消费者释放时保留自身资源直到自己的操作结束，共用服务则拥有准入预约与结算。Client 请求捕获仍为瞬态且不可变。隐藏不支持的控件或格式化确认都不提供 Host 授权、回滚或模型执行证据。

## 考虑过的替代方案

**每个 Artifact 表面各建收据映射** 会重复接受恢复，并让重试依赖视图生命周期。**Artifact 核心调用 API 控制器** 会反转所有权。**修改消息来源字段或新增事件** 会为 `UserMessage.id` 已有的身份再添持久机制。**先验证当前源码再查接受记录** 会拒绝成功更新后的安全重试。**旧身份配新数据重试** 会替换用户确认的问题。

## 影响

旧同步 Artifact `record` 保持 legacy，不宣传幂等性。新的稳定提交需要共用服务，缺席时明确报错。确认只证明输入已接受。身份与哈希随本 Session 自有用户角色输入线性增长，保留它们避免复活已取消或编辑的输入。所有者明确记录复制与哈希成本，不静默过期收据。

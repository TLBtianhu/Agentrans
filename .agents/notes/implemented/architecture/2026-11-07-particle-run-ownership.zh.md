# Agent Note: 粒子运行在预览与导出中保留同一计算

Status: implemented

[English](2026-11-07-particle-run-ownership.md) | 中文

## 问题

粒子预览与导出播放器使用不同的积分顺序。查看源码或切换布局导致视图重新挂载时，预览持有的状态也会丢失。稳定的 Artifact 身份没有保留用户正在检查的实验。

## 决策

纯[粒子运行模块](../../../../packages/artifact/artifact/src/particle-runtime.ts)负责显式 Euler 求值。绝对步数决定时间、位置、速度和有界轨迹。闭式求和保留预览的积分顺序，计算工作量不随经过步数增加。运行版本 1 标识该计算；步数检查点必须配合同一源码修订使用。

SessionBinding 的交互所有者为每个节点和 Artifact 修订持有一次计算。已挂载渲染器通过框架 keyed hook 读取计算，并接收命令回调。查看源码与切换布局会保留计算；隐藏会暂停播放，源码替换或最后一个渲染器释放会丢弃计算。物理预览生命周期与就绪由[另一所有者](2026-11-07-artifact-runtime-reports.zh.md)负责。HTML 导出捕获当前步数并使用同一求值器。

## 考虑过的替代方案

**各视图各自持有模拟**会在呈现方式改变时丢失状态，也让导出自行实现另一套实验。只共享渲染器不能解决这两个问题。

**逐步记入日志或立即增加持久检查点**会在用户工作流形成前引入 Session 兼容与恢复政策。本切片保持本地运行，只有明确确认后才增加模型可见输入。

**重放此前所有步骤**会让 seek 成本取决于时长和步长。恒定重力允许有界求值；更通用的解算器需要各自的执行限制。

## 影响

数值失败会保留最后有限状态并停止推进。检查点不能独立标识作品，也不能恢复另一修订。[已保存观察](2026-11-07-saved-artifact-observations.zh.md)将它们与完整持久源码配对；未保存运行仍是瞬态。比较命令路由和后台导出任务仍需单独实现。HTML 模板及其他场景类型保留当前状态归属。

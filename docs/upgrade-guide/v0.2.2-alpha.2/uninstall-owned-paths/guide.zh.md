# 处理未完成的卸载

[English](guide.md) | 中文

## 变更

生产卸载 CLI 在删除前检查安装根、其祖先和每个选中删除路径。这些路径中的符号链接或 junction 会以 `UNINSTALL_PATH_UNSAFE` 拒绝，预检期间不删除任何选中路径。普通选中子树内部的链接只解除链接，不访问目标。缺失的选中路径仍可安全重试。

Windows NSIS 卸载在原生清理报告拒绝或删除失败时，以非零退出码停止。它保留卸载注册和重试入口，不再显示成功完成。此前删除的内容可能已经生效。交互错误说明恢复方式，静默失败保留独立诊断报告。

共用注册项和快捷方式也必须属于请求中的安装。`InstallLocation`、快捷方式目标、工作目录或参数属于其它用途时，在删除应用前拒绝清理。缺失元数据不授权删除其它安装的快捷方式。

CLI 在错误 JSON 中保留已完成操作、失败操作及可用的原因代码。两个入口都不会回滚已完成删除。详见[库](../../../../packages/boot/product-layout/README.zh.md)及 [Windows 卸载规则](../../../../apps/desktop/README.zh.md#windows-uninstall-rules)。

## 迁移

1. 卸载前结束此安装的应用和 CLI 进程。安装根及选中类别根应为普通目录；检查被报告的链接路径，不删除其目标，也不把清理重定向到目标。
2. 自动化将非零退出视为卸载未完成。保留报告或 CLI 错误 JSON，并在字段存在时检查 `completed` 和 `failedOperation`；应用可执行文件消失不等于清理完成。
3. 解决报告中的路径或文件占用问题，再明确重试同一范围。缺失路径允许重试，所选路径删除成功后才清理注册。保留会话、设置、模型、运行时和导出仍遵循所选范围。
4. 在一次性安装中验证失败处理：在 junction 目标保留外部哨兵，确认拒绝后卸载注册仍在，只移除测试链接，再确认明确重试完成。使用 Desktop README 链接的隔离原生测试入口，不把现有用户或开发数据当作夹具。

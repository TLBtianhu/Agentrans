# 将 SDK 进程关闭交给启动器

[English](guide.md) | 中文

## 变更

SDK 服务插件不再在协议关闭后清理根上下文或调用 `process.exit()`。它在响应刷新后请求启动器的 `appExit`。启动器负责 profile 与代理清理，以及进程自然退出。成功的协议响应仍表示 SDK 自有资源已清理。清理错误保留 JSON-RPC 错误响应并请求以 1 退出；刷新失败也请求以 1 退出。

插件在挂载时要求 `appExit` 或其仅供运行时使用的 `exit` 钩子。该钩子现在表示退出请求，不再意味着插件已清理根上下文。此要求不影响直接使用 `HarnessSdkJsonRpcServer` 类。默认进程 stdin 仅在协议退出时暂停。注入的输入与只做 HMR 卸载的路径保留调用方的流所有权。

## 迁移

1. 继续通过 `dsh --profile sdk`、`sdk-minimal` 或自定义 profile 启动应用。启动器会提供 `appExit`。移除假定 SDK 插件负责根清理或强制终止进程的代码。
2. 手动挂载插件的测试须提供 `appExit` 或已有的 `exit` 钩子。将其视为请求；真正的应用所有者须完成清理和进程退出。使用注入流的代码须释放自己拥有的输入活动。
3. 分别检查关闭响应与子进程退出。成功时返回 `{}` 后以 0 退出；错误响应与刷新失败保留失败退出状态。在保持父进程 stdin 管道打开时，确认子进程自然完成。启动器的清理时限从收到退出请求后开始，不覆盖此前的 SDK 清理或响应刷新；客户端请求与关闭超时仍各自独立。

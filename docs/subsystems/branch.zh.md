# 手动分支

[English](branch.md) | 中文

手动分支是从另一个 Session 的精确前缀创建的独立 Session。它的 `SessionId` 就是分支身份。`header.parentSession` 记录直接来源；`origin` 保持缺省，因此普通手动分支不是 subagent。

## 开岔与谱系

在包含端点的 `atSeq` 开岔会继承该事件之前的源前缀，以 `session/end-seed` 标记继承切口，并用 fork 专用结果闭合未完成的工具、步骤和轮次。源日志不变。嵌套分支指向直接父级，而不是根节点。

`inheritedEventCount` 只计复制的源事件，不计 seed 标记和合成关闭事件。非空分支的源切口为 `inheritedEventCount - 1`，不需要再存一份 `atSeq`。

子分支只从自己的日志派生模型消息。开岔后父级新增的事件和兄弟对话不会进入该子分支。嵌套子分支继承直接父级的前缀，其中已经包含相关祖先。

## 从回答选段开启探究

在已完成的回答中选中文字，再点「从选中内容开探究分支」。开岔会继承完整轮次，子分支可以操作同一张函数图。Host 核对选段是否与指定助手消息的 UTF-16 范围一致，并存入子分支的 header。打开分支时父对话保持原样，也不会启动模型轮次。

浏览器将选段作为可移除的引用放进新分支草稿。在同一标签页刷新，可以恢复当前草稿和已锁定的函数图读数。移除引用或成功发送后，再打开分支时会恢复相应的草稿状态。

如果探究分支打开失败，点「重试」即可用原选段继续同一次请求。如果子会话已经保存，Host 会复用它并补齐未完成的工作区挂载，随后浏览器打开该会话并预填草稿。成功打开后再次发起探究会创建独立分支。

对应的分支入口显示在原回答下方。「查看回流结果」会打开该分支已确认的追问证据，复现保存的状态。同一分支有多次回流时，可以按确认顺序选择。CSV 选项显示保存的分组、聚合方式和读数。粒子实验暂停在记录的步数。BFS 可以从锁定的当前节点、队列和已访问节点继续。半加器可以先核对已保存的输入和输出，再切换输入。对于原始 CSV 图表，「查看参与行」会读取锁定分组的原始记录，无需重算聚合值。证据卡的「定位原句」会滚回原回答并高亮当时的选段。刷新后仍可使用这些入口，查看时无需调用模型。

探究入口目前支持已完成轮次的最终回答中连续的原文，长度不超过 512 个 UTF-16 代码单元。与旧版读取器的兼容情况见 [Session 格式变更记录](../persistence-changes/2026-11-16-inquiry-fork-anchor.zh.md)。

同一探究分支有多次原始 CSV 回流时，可从「查看回流结果 → 对照两次回流」选中源 CSV 和分组相同的两次结果。对照按确认顺序展示锁定读数，并标明哪些记录两边都参与。宿主从源附件核对参与行，聚合值沿用已保存的读数。同一标签页刷新后，从原回答重新打开对照即可恢复上次选中的组合。查看时无需调用模型。

点「核对并附到追问」确认当前显示的一页。换一组对照或翻页后，编辑框仍保留已确认的附件。发送问题后，可以从该追问的「复现附加对照」打开同一页，核对两次锁定读数和参与记录。复现使用随问题保存的页面，无需读取 CSV。

在已发送的对照中，点任一侧的「查看原始回流」打开当时锁定的证据卡。「返回对照」会展开原对照，并将焦点移回刚才点击的入口。同一标签页刷新后仍可返回。打开回流和返回对照都使用已保存的对话历史。

点「下载 HTML 对照」可把已确认的对照和两张原始回流卡存进同一个文件。离线展开任一卡片，就能核对原结论、保存的图表修订和已核对页中的参与记录。下载使用已保存的历史，无需读取 CSV 或重算结果。

「下载 JSON 对照」也会带上两张原始回流卡。切到另一条对话后，点「导入 CSV 对照」可核对两张卡，并看到「用户导入」标记。确认附件后，两张卡会随同一页保存，发出追问并刷新后仍可展开。

在已发送并标有「用户导入」的回流对照里，点「复用整份回流对照」可核对原锁定页和两张卡，再一起附到新追问。确认后，核对内容和导入标记会一起保存在草稿里，刷新后仍能接着提问。

复用后，可以从草稿或已发送的追问点「查看这次复用的来源追问」。即使还有一张读数完全相同的卡，刷新后仍会打开本次选中的那张，并可展开它的两张原始回流卡。

从草稿或已发送的对照点「查看完整来源链」，可以查看每次复用实际选中的追问。打开来源后可核对它的两张原始卡，在较早来源刷新后也能逐层返回。回到草稿时会恢复原文字、光标和锁定附件。查看过程只读取已保存的对话历史。

草稿附件也可以从任一侧点「查看原始回流」。在证据卡内点击「返回草稿」可恢复原问题、光标和已确认的附件，同一标签页刷新后也能返回。返回后会清除本次路径，再次刷新会留在对话中。

## 确认后的结论回流

`SessionBranchResultRequest` 包含直接父级 `sessionId`、子分支 `branchSessionId` 和子分支自有的持久 `assistant/message` 序号 `resultSeq`。请求不携带结论文本。Host 重新读取精确的子事件，并校验消息 id 和非空可见文本。

`SessionBranchResultValue` 包含 `parentSessionId`、父级本地 `eventSeq` 和父级本地 `messageId`。以相同确认内容重试同一 `(parent, branch, resultSeq)` 会返回已有回执，不重复追加。该结论使用不同内容时报告 `session/branch-result-conflict`，包括纯结论与带证据回流之间的冲突。

接受的结论在父级当前尾部形成新的普通 `user/message`，其 source 为 `branch-result`，包含：

| 字段 | 含义 |
|---|---|
| `branchSessionId` | 拥有该结论的子 Session |
| `resultSeq` | 精确的子事件序号 |
| `resultMessageId` | 子 assistant 消息的稳定 id |
| `form` | `notice` |

子事件序号不写入 `sourceEventSeqs`，后者只接受同一 Session 内更早的事件。确认回流创建父级本地的新消息身份，不改写历史，也不启动模型轮次。

非分支、subagent、错误父级、继承事件、结果不存在或可见文本为空都会被拒绝。空闲父级通过 maintenance 串行化追加并 flush；运行中的父级返回 busy，不隐式 steer。

普通回流和 [Artifact 证据桥接](../../packages/artifact/artifact-branch/README.zh.md)共用 Host 专用的 `session-branch/admission` 操作。它在持有父级 maintenance 时比较已有内容，只对新消息追加并 flush。操作开始后的失败可能留下未知结果；重试同一选择可找回回执。只有未能进入 maintenance 的失败才报告 busy。

证据桥接从同一个不可变子分支切面读取结论和用户所选证据。它把证据作为普通文本块附加到父级的 `branch-result` 消息中。选择规则和复现见 [Artifact 分支证据](artifact.zh.md)。

## 验证

keyless [branch-result 场景](../../apps/web/tests/branch-result.e2e.ts) 通过实际 Web 组合重放父级回答和独立的子级回答。浏览器从父级开岔，打开子级自有结论的预览，先取消一次而不回流，然后再确认。测试检查预览不包含 reasoning、父级只新增一条携带子级引用和可见文本的 `branch-result` 用户消息，并且确认前后都不启动父级模型轮次。

[分支证据场景](../../apps/web/tests/branch-evidence.e2e.ts) 将已保存对比和原生实验追问读数随子分支结论一同回流，并在刷新前后打开父对话中的确认修订和读数。对比用例还核对响应丢失后的相同请求重试、更换证据时的冲突，以及父级同名 Artifact 的保留。

[真实模型探究场景](../../apps/web/tests/artifact-live.e2e.ts) 用浏览器指针选中「切线斜率」，操作继承的函数图，并核对发给 DeepSeek 的锁定读数。回流和刷新后，测试核对原读数、选段的可见高亮，以及返回同一子分支的入口。

## 限制

- 前缀继承使用现有 Session fork seed，不是零复制的跨 Session overlay。
- 回流只复制选定的可见文本块及其引用，不复制子分支全文、工具、推理或兄弟状态。
- 谱系支持导航与校验，不提供自动语义合并或冲突解决。
